# 位置证据与空间表达方法

本文说明仓库当前如何把公开资料转成地图上的位置提示，以及这些提示不能证明什么。它是可审计的数据说明，不是洪水风险图、测绘成果或主管部门的边界认定。

## 当前数据快照

截至 2026-09-14：

- 名录对象：97 处；
- 有资料推定范围：72 处；
- 因第三方地图定位材料不适合再分发而撤下空间几何：25 处；
- 位置确信度：高 3 处、中 69 处、暂不判断 25 处；
- 实地核验：0 处。

网页始终展示完整的 97 处名录。没有可发布空间几何的对象显示“无法找到”，不会用省市中心、单一地标或任意圆形补齐。

## 记录结构

`data/zones.js` 保存名录名称和流域等目录信息。`data/location-evidence.js` 保存来源链接、行政区交叉核对、结论和限制。`data/location-boundaries.js` 保存仍可发布的 72 个资料推定范围；这些记录的 `quality` 均为 `human-reviewed-hypothesis`，`boundaryClass` 均为 `guess-boundary-for-display`。字段名中的“reviewed”只表示项目内审阅，不表示主管部门审核或实地验证。

部分资料摘录和几何草案曾使用自动化或大语言模型辅助整理。未随仓库提供的内部运行路径、候选文件和提取产物已从发布数据中删除，因此不能把“项目内审阅”理解为完整可复现的独立验证。

部分 `data/location-cache.js` 记录来自 OpenStreetMap，相关数据库部分受 ODbL 1.0 约束。坐标系字段仅用于正确渲染，不代表坐标由官方测量获得。

## 来源处理

证据记录保留公开网页、政府文件、已发表资料或新闻的标题与链接。链接用于让读者回到原文检查，不等于项目取得原文版权，也不自动证明其中的描述正确。此次公开前清理已执行以下规则：

1. 删除全部高德 `placeSearch` 候选、上下文地标和原始计数；
2. 删除单独的高德 D 级位置缓存；
3. 删除标记为“ChatGPT 引用、须结合原文核对”或“未单独逐页核验”的来源条目；
4. 删除包含高德地物坐标或以其配准的 25 个推定范围；
5. 保留的在线高德地点搜索只在用户当前会话中展示，不写入仓库数据。

未来新增来源时，应记录原始网址、标题、发布者、访问日期、直接支持的地理陈述和可再分发依据。无法逐页核对的自动生成引用不得计入确信度。

## 确信度规则

确信度描述的是“现有记录支持某种位置表达的程度”，不描述洪水发生概率，也不等于边界精度。

- `H1 / 确信度高`：记录中有可用于定位的官方图件，且对应空间几何未因许可问题撤下。当前 3 处。
- `M1 / 确信度中`：至少一条保留的公开资料支持行政区域或模糊位置，行政区核对不冲突，且有可发布的资料推定范围。当前 69 处。
- `N1 / 暂不判断`：清理后没有可发布的空间几何，或证据不足、冲突。当前 25 处。

同名地点搜索不能提高仓库数据的确信度。百科线索只能帮助发现检索词；未由公开资料交叉核验的线索不得决定位置或边界。代码中的 `calculateLocationConfidence` 只计算证据资格，并接受 `hasPublishableBoundary` 条件；发布数据还必须同时通过第三方许可清理。

## 空间表达

保留的几何来自记录中的公开资料线索、项目内人工描绘或适用许可的数据。网页以实线和浅色填充表示“推定范围”，以虚线表示只能落实到行政范围的记录。每个详情页同时显示：

- 资料面积与图示面积（若有）；
- 公开来源链接；
- 未找到官方图件、未经实地核验等限制；
- “不是主管部门发布的法定边界”的固定提醒。

人工描绘会受到原图分辨率、配准、地名歧义、河道变化和资料年代影响。相邻范围为可读性做过的视觉分隔也不构成真实界线。

## 复核清单

任何准备把某一对象用于现实决策的人，都应停止使用本网页结论，转而向有权水行政主管部门索取现行法定材料。项目维护者更新记录时至少应：

1. 打开并逐页核对原始资料，记录直接支持位置的页码或段落；
2. 核对同名异地、行政区调整、资料日期和坐标系；
3. 确认地图或数据库的许可允许仓库存储和再分发；
4. 将原始图件与推定几何并排复核，记录偏差和未知闭合段；
5. 不因面积数值相近而把示意图升级为法定边界；
6. 更新本页统计，并保持 `fieldVerified: false`，除非确有可审计的实地核验记录。

发现具体数据错误时，可提交不含个人敏感信息的 GitHub issue；安全漏洞请按 `SECURITY.md` 报告。
