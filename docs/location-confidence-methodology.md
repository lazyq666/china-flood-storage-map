# 位置证据与空间表达方法

本文说明仓库当前如何把公开资料转成地图上的位置提示，以及这些提示不能证明什么。它是可审计的数据说明，不是洪水风险图、测绘成果或主管部门的边界认定。

## 当前数据快照

截至 2026-09-14：

- 名录对象：97 处；
- 有资料推定范围：97 处；
- 位置确信度：高 30 处、中 67 处；
- 实地核验：0 处。

网页展示完整的 97 处名录及其资料推定范围。部分范围使用第三方地点检索结果或行政区范围辅助定位，均不代表法定边界或实地测量成果。

## 记录结构

`data/zones.js` 保存名录名称和流域等目录信息。`data/location-evidence.js` 保存来源链接、行政区交叉核对、结论和限制。`data/location-boundaries.js` 保存 97 个资料推定范围；这些记录的 `quality` 均为 `human-reviewed-hypothesis`，`boundaryClass` 均为 `guess-boundary-for-display`。字段名中的“reviewed”只表示项目内审阅，不表示主管部门审核或实地验证。

部分资料摘录和几何草案曾使用自动化或大语言模型辅助整理，个别记录还保留整理流程中的相对路径和候选说明。仓库未必包含这些流程的全部原始输入，因此不能把“项目内审阅”理解为完整可复现的独立验证。

部分 `data/location-cache.js` 记录来自 OpenStreetMap，相关数据库部分受 ODbL 1.0 约束。坐标系字段仅用于正确渲染，不代表坐标由官方测量获得。

## 来源处理

证据记录保留公开网页、政府文件、已发表资料或新闻的标题与链接。链接用于让读者回到原文检查，不等于项目取得原文版权，也不自动证明其中的描述正确。

当前数据保留整理阶段的高德 `placeSearch` 候选、上下文地标、D 级位置缓存，以及使用这些线索辅助配准的推定范围。此类记录只能作为位置线索，不代表高德或主管部门确认边界；其使用和再分发仍受相应第三方条款约束。标记为“ChatGPT 引用、须结合原文核对”或尚未逐页核验的条目只能作为待核线索，不能视作独立证据。

未来新增来源时，应记录原始网址、标题、发布者、访问日期、直接支持的地理陈述和可再分发依据。无法逐页核对的自动生成引用不得计入确信度。

## 确信度规则

确信度描述的是“现有记录支持某种位置表达的程度”，不描述洪水发生概率，也不等于边界精度。

- `H1 / 确信度高`：记录中有可用于定位的官方图件。
- `H2 / H3 / 确信度高`：同名候选经公开资料和行政区信息交叉核对后形成唯一或已消歧的位置结论。
- `M1 / 确信度中`：未找到唯一同名地物，但公开资料能够支持一个模糊位置。
- `N1 / 暂不判断`：现有候选和公开资料仍不足或互相冲突。

同名地点搜索必须与公开资料及行政区信息交叉核对后才能提高确信度。百科线索只能帮助发现检索词；未由公开资料交叉核验的线索不得单独决定位置或边界。

## 空间表达

保留的几何来自记录中的公开资料线索、项目内人工描绘或适用许可的数据。网页以实线和浅色填充表示“推定范围”，以虚线表示只能落实到行政范围的记录。每个详情页同时显示：

- 资料面积与图示面积（若有）；
- 公开来源链接；
- 未找到官方图件、未经实地核验等限制；
- “不是主管部门发布的法定边界”的固定提醒。

人工描绘会受到原图分辨率、配准、地名歧义、河道变化和资料年代影响。相邻范围为可读性做过的视觉分隔也不构成真实界线。

## 复核清单

任何准备把某一对象用于现实决策的人，都应停止使用本网页结论，转而向有权水行政主管部门索取现行法定材料。项目维护者更新记录时至少应：

1. 打开并逐页核对原始资料，记录直接支持位置的页码或段落；
2. 核对同名异地、行政区调整、资料日期和坐标系；
3. 确认地图或数据库的许可允许仓库存储和再分发；
4. 将原始图件与推定几何并排复核，记录偏差和未知闭合段；
5. 不因面积数值相近而把示意图升级为法定边界；
6. 更新本页统计，并保持 `fieldVerified: false`，除非确有可审计的实地核验记录。

发现具体数据错误时，可提交不含个人敏感信息的 GitHub issue；安全漏洞请按 `SECURITY.md` 报告。
